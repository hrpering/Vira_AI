# Studios

A Studio connects an open-source project or repeatable task to visible inputs, steps, permissions, run state, review points, and outputs. It is not only a “run” button: people should know what is queued, what is complete, what needs approval, and what result will remain.

A research Studio might collect sources, synthesize findings, send uncertain claims for review, generate a brief, and save a portable output. The Studio manifest makes that expectation inspectable before the run begins.

See [`specs/studio-manifest.md`](../specs/studio-manifest.md) and [`examples/studios/studio-manifest.yaml`](../examples/studios/studio-manifest.yaml).
